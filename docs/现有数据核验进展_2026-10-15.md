## 2. 27 份解析试跑实际完成了什么

沿用上一轮每目录 3 份的固定样本，未因检测结果好坏重新挑选。样本含已知重复波形，所以 27 条记录对应 26 份不同波形，不是 27 名独立患者，也不是随机样本。

- 对每份 `.nb`、`.ba`、`.bd` 全成员读取，校验 ZIP CRC，并保存各成员 SHA256。27 份全部通过已知二进制结构检查；这不是整个 CCM 的所有成员完整性认证。
- `.nb` 仍采用“12 字节头、小端 int16、8 个交错存储通道、头部采样率 250 Hz”的解释。导联名称、幅值增益和单位尚未确认，图片纵轴为原始计数。
- `.ba` 第 5 个 int32 字段作为候选事件采样索引；`.bd` 第 1 个 int32 字段作为原始类型码。两者按行对应仍属待验证假设。
- 保存 **2,849,056 个候选 RR 间隔**，原事件全部保留，无插补、无跨缺口重建 NN；`nn_valid`、`normal_beat_verified` 全部为空。
- 保存 **7,329 个 5 分钟窗口**：21 份有时钟的记录产生 5,743 个本地钟点窗口；6 份缺时钟的记录产生 1,586 个明确标为 `relative_only` 的相对时间窗口。后者不能用于昼夜分析。
- 记录首尾不足 5 分钟的窗口单列。任意钟点起始的 24 小时记录可能触及 289 个格子，但只有 287 个完整格子；没有把两个不完整格子当作完整覆盖。
- 每份固定在记录偏移 300 秒、6 小时、12 小时、18 小时尝试读取 60 秒片段，前后各加 10 秒检测缓冲；不足记录长度的片段跳过。共保存 **107 个八通道原始片段、214 次通道对照、27 张对照图**。

原始文件操作均为读取，处理前后检查了文件大小与修改时间一致；王世豪两份本轮 `.nb` SHA256 再次与之前完整哈希结果一致。

## 3. 独立算法对照：支持部分事件定位，但尚不是准确率

复用 [WFDB XQRS](https://wfdb.readthedocs.io/en/latest/processing.html#qrs-detectors)，没有重写检测器。实际固定版本为 wfdb 4.1.2，使用默认学习参数，在未滤波的原始计数上独立运行。固定存储通道 Ch2、Ch7，不根据每段结果选择较好的通道。匹配采用有序一对一、±50 ms 容差；250 Hz 整数采样实际允许最大 12 个采样点，即 48 ms。

| 存储通道 | 厂商候选事件数 | XQRS 候选数 | 匹配数 | 匹配数 / 厂商事件 | 匹配数 / XQRS 事件 |
|---|---:|---:|---:|---:|---:|
| Ch2 | 8,472 | 9,010 | 8,060 | 95.14% | 89.46% |
| Ch7 | 8,472 | 8,693 | 8,022 | 94.69% | 92.28% |

这些是**算法间一致程度，不能称为敏感度、阳性预测值或验证准确率**。两通道的厂商事件是同一批，不能相加作为独立样本；重复波形也未从本次工程试跑统计剔除。

有厂商事件的 103 个片段中，厂商事件匹配比例低于 90% 的分别有 5 个、6 个；另外 4 个片段没有厂商事件，其比例记为空，不人为记为 0% 或 100%。按任一侧匹配不足 90%、任一算法无事件的规则，共列出 22 个“通道—片段”优先复核项目，见 [review_priority.json](../outputs/verification/review_priority.json)。90% 仅用于安排人工复核顺序，不是已冻结的 HRV 质控阈值。

图像检查看到：同一时段可能 Ch2 噪声明显而 Ch7 仍有清楚心搏；另一些明显噪声片段，XQRS 仍报出大量候选峰。因此不能把一个通道的失败推广为整份记录失败，也不能用 XQRS 自动填满厂商空档。

## 4. 两项会影响后续 HRV 的问题

### 4.1 长时间无事件不能只靠 RR 变化率发现

本批 7,329 个窗口中，307 个没有厂商候选事件，其中 **299 个具有完整 300 秒波形载荷**。波形载荷存在不代表信号质量合格，更不代表 NN 覆盖。

| 匿名记录 | 现象 | 含义 |
|---|---|---|
| `r_9e025c62597a9ff90a18` | 总跨度 73,020 秒；最大相邻事件空档 39,368.984 秒，约 10.9 小时；133 个完整窗口无事件；相邻 RR >20% 仅 14 次 | 不能把“异常间隔占比很低”解释为信号可用；这个长间隔是事件空档，不能解释成生理心搏间隔 |
| `r_7e978b9f0cae8f5514ab` | 总跨度 70,260 秒，最后事件在 26,818.4 秒；144 个完整窗口无事件 | 不能按原始文件时长宣称接近全天有效 HRV |

上述记录的部分抽查片段存在明显噪声，尚不足以判定全部空档的原因；可能涉及信号问题、未分析区间或标注版本。详细位置见 [rr_gap_diagnostics.json](../outputs/verification/rr_gap_diagnostics.json)。暂不自动补齐，也不自动删除整例。

全部原始候选间隔中共有 28,117 个相邻变化超过 20% 的标记，只作为提示。零值比例、恒定通道及 int16 极值也仅是可复查的简单诊断量，不能据此给出有效时长。

### 4.2 类型码与报告数量不完全对应

27 份中有 21 份 XML 报告可作计数对照。下列仅为待验证的映射假设，差值为“代码数量减报告数量”：

| 假设 | 数量相等 | 两侧均为 0 的数量 | 差值范围 |
|---|---:|---:|---:|
| code 1 ↔ SinusNormallHrCount | 10/21（47.62%） | 0 | −19,998 至 +311 |
| code 2 ↔ SVRCount | 12/21（57.14%） | 4 | −159 至 +9 |
| code 3 ↔ VRCount | 19/21（90.48%） | 14 | −134 至 0 |
| code 6 ↔ ArtifactCount | 21/21（100%） | 12 | 0 |

code 6 有较强的计数对应证据，但仍需事件位置和软件类型名称核验。code 3 的多数一致来自双方均为零，证据强度有限。code 1 的差异不能直接证明代码含义错误，也可能来自分析区间或报告版本差异；但足以说明目前不能直接将它们全部判为可靠正常搏动。code 13、99 等也未自行命名。

## 6. 下一步的实际条件

现阶段先完成 R 峰和正常搏动类型的参考核验，再冻结信号质量与 NN 规则；之后才计算 G/C/N。当前没有发布全局 HRV、Cosinor 或非线性特征，也没有训练分类模型。不能把本轮“工程检查通过”写成 README 第一阶段全部验收通过。

人工参考可直接利用现有 NPZ，不依赖甲方重导全部 CCM。先用 [字段与复核说明](核验产物字段与人工复核说明.md) 中的无标记绘图命令查看八通道，再填写 R 峰采样索引及类型；类型无法确定时保留未知。对照图含厂商与算法标记，不应提前给盲法参考标注者观看。

能够得到原软件少量对应片段的“搏动时间＋类型名称”导出，会明显减少类型码核验工作；它仍是对照来源，不自动成为人工真值。患者对应表和标签裁决仍按此前最小信息表补充即可，不要求重新导出全部 CCM。
