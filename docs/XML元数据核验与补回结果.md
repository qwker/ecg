日期：2026-10-13。本轮范围已完成：缺配置记录清点、XML/configJson 交叉核对、字段补回、必要 PDF 检查和待补充表。没有开展 HRV 特征计算或分类训练。

## 结论

不需要甲方重新导出全部 CCM。66 份缺配置记录中，26 份可从内置 XML 补回采集开始日期时间、名义记录时长和性别，其中 24 份可补回年龄。剩余 40 份既没有 XML，也没有内置 PDF，应提供对应的最小信息表。

## 2. XML/configJson 交叉核对

以记录为单位统计，不能把同一记录的多个配置版本或两个报告节点算作多个独立样本。读取并保存所有配置来源，先检查配置内部一致性，再与 XML 比较。

| 字段及映射 | 可比较记录数 | 一致 | 不一致 | 不可比较 | 一致率 |
|---|---:|---:|---:|---:|---:|
| XML RecordDate+RecordStartDateTime ↔ CollectBeginTime | 806 | 806 | 0 | 0 | 100% |
| XML RecordStartDate+RecordStartDateTime ↔ CollectBeginTime | 806 | 806 | 0 | 0 | 100% |
| XML RecordTotalCollectTimeSpan ↔ CollectAllSeconds | 806 | 806 | 0 | 0 | 100% |
| XML OriCollectAllSeconds ↔ CollectAllSeconds | 806 | 806 | 0 | 0 | 100% |
| XML Age ↔ Patient.Age、AgeUnit | 806 | 806 | 0 | 0 | 100% |
| XML Sex ↔ Patient.Gender | 806 | 806 | 0 | 0 | 100% |
| XML EcgReportId ↔ 报告 Id | 806 | 806 | 0 | 0 | 100% |
| XML PatientID ↔ Patient.IdCard | 804 | 804 | 0 | 2 | 100% |
| XML SourceNo ↔ Patient.SourceNo | 804 | 804 | 0 | 2 | 100% |
| XML Name ↔ Patient.Name | 806 | 806 | 0 | 0 | 100% |
| XML Birthday ↔ Patient.BirthDate | 804 | 804 | 0 | 2 | 100% |

身份字段/来源编号不可比较的两份为宋君、李轶，两侧均为空；其出生日期两侧均为无效占位日期。缺值不计作“一致”，一致率分母仅为可比较记录数。姓名、身份编号只用于匹配与查重，不作为分类输入。

观察到的格式：

- RecordDate 为 `YYYY-MM-DD`；RecordStartDate 为 `MM月DD日YYYY年`；RecordStartDateTime 为 `HH:MM:SS`。
- 时长为中文小时/分/秒，或数值秒；未将 AnalysisTime/AnalysisTimeSeconds 当作原始记录跨度。
- 年龄为整数加“岁”，配置年龄单位代码 0；性别为“男/女”，与配置代码 1/2 分别对应（男436、女370）。
- Birthday 为斜杠分隔的年月日；身份/来源字段同时存在纯数字和文本形式。XML 字段名 PatientID 不能据名称直接解释成统一研究患者编号。
- 缺配置记录中用于补回的字段格式均出现在配对验证记录中。

本次以“至少20条可比较记录且没有差异”作为字段映射通过条件。实际达到上述数量，未发现 XML/configJson 差异，也未发现补回记录的 XML 两种起始日期表达之间的冲突。26 份 XML 名义时长与 NB 文件头推算时长差异均不超过1秒。

**100% 一致只说明这批来源的字段映射一致；XML 和配置可能来自同一软件系统，不能视作独立临床真值验证。** 也未证明配置缺失人群的所有其他分析参数都等同。

## 5. 交付与验证范围

- `outputs/metadata/元数据补回与待补充表.xlsx`：两张表，各66条记录；一张保存补回字段与来源、状态，一张为甲方填写最小信息表。包含姓名，供本地核对。
- `private/metadata/metadata_table.json`：结构化补回表，每个字段保留来源成员序号、成员SHA-256、字段路径、核验状态，并关联 PDF 补查结论。
- `private/metadata/source_evidence.json`：XML、各版本配置的字段值与比较结果。身份编号保留HMAC匹配标识；原始值仍可通过源CCM及成员序号追溯。出现冲突不覆盖任何来源。
- `outputs/metadata/validation_summary.json`：一致率、格式类型、缺失及解析状态的机器可读汇总。
- `private/metadata/pdf_review/review_summary.json`：PDF检查的字段与来源哈希。

检查通过：878份记录的元数据文件结构读取没有解析异常，空字段及占位值另行标记；66条输出编号唯一；日期、年龄逐行核对；Excel长编号按文本保存，未丢失末尾数字；患者研究编号和确认标签的待填列为空。解析器的空值、占位生日、闰日、来源冲突保留路径已做边界检查。

原始CCM只读，读取前后文件大小和修改时间一致；未对所有原始文件重做完整哈希，因此不把这个检查称为全量字节级校验。元数据补回完成不等于波形、正常搏动类型和NN提取已验收。
