# 首轮数据审查与实施建议

日期：2026-10-13。依据当前 README 和本次实际读取结果。原始 CCM、README 均未改写，未训练模型。本轮完成全量轻量清点、重复候选复核、27 份结构试读及开源调研；**尚未完成临床标签裁决、独立心搏标注和可信 NN/HRV 特征试算**。

## 1. 当前决策

先修复标签和数据可追溯性，再进入特征试算。现阶段实现九分类训练、SHAP 或复杂软件框架，都不能解决已经发现的输入问题。

最重要的发现是：**同一份完整波形同时出现在“焦虑”和“正常”类别；正常组 19/24 份记录没有 `.configJson`。** 若忽略这些问题，分类成绩可能受标签错误、重复记录和采集/导出差异影响。

## 3. 格式证据及其限度

### 全部 878 份 NB 文件头

全部符合以下长度关系：前 12 字节可按小端三个 uint32 读为 `0、250、帧数`，文件剩余长度为 `帧数×16`。这支持“250 Hz、每帧 8 个 int16 存储通道”的假设。

文件头推算跨度为 16.3633–24 h；484 份恰为 24 h；1 份不足 18 h，14 份不足 22 h。有配置的 812 份，其声明时长与帧数推算时长差异均不超过 1 秒。**这些是名义跨度，不是有效 ECG 或有效 NN 时长。**

配置声明 12 导联。品牌为 NALONG，型号主要为 H1201，少量写作 H1200_H1201；这只说明配置内容，分析软件的精确版本仍未知。没有为 8 个存储通道擅自命名导联或补出另外 4 导联；幅值暂用 raw count，未换算 mV。

有配置的采集起始时间可解析，但字符串均不带时区。中国本地时间可作为后续待确认假设，不能把用户电脑时区直接当作设备时区证据。

### 27 份小样本探查

每类选 3 份，优先包含较短记录、重复波形候选、缺配置记录和多配置版本。固定生成记录开始后 60–70 秒、300–310 秒两个窗口，共 54 个窗口的 8 通道图。选择依据写入 evidence.json；它不是代表性随机抽样，也未覆盖全天各时段。

27/27 份符合以下**待验证二进制布局**：

- BA：版本字 2；字节偏移 14 的 uint32 为 44；偏移 18 为事件数；总长度 = 4096 + 事件数×44。
- BD：版本字 1；相同偏移的记录宽度为 48；总长度 = 4096 + 事件数×48。27 份 BA/BD 事件数均相等。
- BA 每条记录暂按 11 个小端 int32 解释。零起算第 4 列（即第 5 个 int32）可作为候选搏动采样位置；27 份均严格递增且落在名义帧数范围内。
- BD 第 0 列出现原始代码 `1、2、3、6、13、99`。**未把 1 直接叫作正常搏动，其他代码也没有自行解释。**

人工式图像浏览抽查了 3 张图，能看到候选标记与主要心搏波形对应，也看到基线漂移和局部噪声。这只支持进一步核验该布局，不能作为独立专家标注，更不能据此报告敏感度、PPV、时间误差或正常搏动识别准确率。

BA/BD 全成员已在这 27 份上读取、校验 CRC 并记录 SHA-256；NB 仅读取前 330 秒，另外重复候选的两个 NB 做了完整哈希及 CRC。其余 NB 没有全量解压或有效覆盖评估。

## 4. 对 README 的具体修正建议

1. **正常组风险应排在模型比较之前。** 样本少之外，还存在已确认的跨类重复和明显的配置缺失差异。优先追溯正常组来源、导出流程及纳入依据；不能用剔除缺配置记录的办法自动解决，否则该组可能所剩极少。
2. **“每个 5 min 内取 256 个连续 NN”需要先检查选择偏差。** 256 个间隔要落在 300 秒内，平均间隔必须不超过约 1.172 秒，相应速率约为 51.2 次/分。较慢心率窗口可能即使干净也凑不齐。这是算术约束，不是医学阈值。试跑应按钟点、类别和心率报告可计算率，再预先确定长度或独立的非线性窗口方案。
3. **固定钟点网格与“288 个窗口”要消除歧义。** 例如 10:08:32 开始的完整 24 h，会触及 289 个按钟点整 5 min 对齐的格子，其中两端不完整。建议保存带日期的半开区间、实际覆盖秒数及边缘窗标记，明确分母；不能把首尾同一钟点的两段拼成连续 NN。
4. **结构通过、波形有效、NN 有效分开验收。** 文件头 24 h 不等于 24 h 可用；类型代码高频出现不等于正常；与另一算法一致也不等于有独立真值。
5. **第一轮特征收敛到最小集合。** 在正常搏动含义确认后，先核对 MeanNN、SDNN、RMSSD、连续对计数和有效覆盖，随后扩展短时频谱、小时曲线和 Cosinor。ULF、DFA-α2、大量非线性特征不作为读通数据的前置目标。
6. **10 折不是当前优先事项。** 先得到已裁决的患者级样本数和类间构成，再确定可行折数。方法不得因模型分数好看而反向改变。

这些建议尚未替换 README 的正式协议；涉及标签定义和临床纳入标准的内容仍需数据提供方确认。

## 6. 交付文件与复现

在项目根目录执行：

```powershell
python scripts/audit_ccm.py
python scripts/audit_ccm.py --verify-duplicates
python scripts/probe_ccm.py
```

审查脚本仅使用标准库；探查图使用本机已有 numpy/matplotlib。原始数据只读；输出和身份映射为本地生成文件。

- `outputs/audit/summary.json`：总体计数与检查限度。
- `outputs/audit/records.jsonl`：逐记录去标识清单，目录标签尚未裁决，不能直接用于训练。
- `outputs/audit/config_evidence.jsonl`：配置来源节点、版本哈希及白名单字段。
- `outputs/audit/patient_candidates.json`：暂定身份组，不是验收后的患者主表。
- `outputs/audit/repeated_identifiers.json`、`repeated_name_hints.json`：重复/冲突线索。
- `outputs/audit/duplicate_hash_verification.json`：两个候选的完整容器及波形哈希。全量清单里的哈希空值表示该清单未做全量哈希，不与此专项复核矛盾。
- `outputs/probe/evidence.json` 和 27 张 PNG：结构证据、抽样依据、待人工核验片段。没有伪造人工参考或临床 HRV。
- `private/record_paths.json`、`private/pseudonym_key.bin`：仅本地保存的原始路径映射和 HMAC 密钥。生成编号为可链接的假名化标识，不是不可逆匿名化。密钥保持不变时重跑编号稳定。

`.gitignore` 已排除原始数据、身份映射和生成结果；未创建远程仓库，也未上传任何患者资料。原始配置还包含本任务不需要的个人信息与软件账户相关字段，脚本不导出这些字段。
